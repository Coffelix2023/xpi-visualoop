## Context

动机见 [proposal.md](proposal.md)。当前 `src/index.ts` 只有状态命令，没有视觉工具、浏览器会话或面板状态。行为契约分别见 [visual-evidence](specs/visual-evidence/spec.md)、[visual-feedback](specs/visual-feedback/spec.md)、[visual-verification](specs/visual-verification/spec.md)。本变更跨越外部进程、证据数据和交互生命周期，因此需要设计文件，不适用条件跳过。

已核对的本地事实：

- `docs/references/browser-harness/pyproject.toml` 为 0.1.13，MIT 许可，提供独立命令；不复制该参考源码。
- `helpers.py` 提供 `page_info()`、`capture_screenshot()`、`js()`、`cdp()` 与标签页操作。截图默认写同一个 `shot.png`，必须由本扩展传入唯一文件路径；它不自动返回完整坐标转换，也不提供图像差异算法。
- `daemon.py:get_ws_url()` 支持显式 `BU_CDP_URL` 连接专用 Chrome；`BU_NAME` 本身只隔离控制器，不创建独立浏览器配置目录。
- `paths.py` 和 `_ipc.py` 支持隔离配置、工作区、运行时及临时目录。不能借用用户默认 daemon 的可变当前标签页。
- 项目安装的 Pi 0.84.4 类型中有 `ctx.isProjectTrusted()` 和会话取消信号；`ExecOptions` 只有 signal、timeout、cwd，不支持 stdin 或独立 env。实现时重新核对安装版本的类型与完整相关文档。
- Glimpse 支持显示本地构造的 HTML（超文本标记语言）和双向消息；框选、缩放坐标转换及会话绑定仍需实现。尚未进行浏览器或面板实测，源码事实不等于端到端兼容性已通过。

## Goals / Non-Goals

**Goals:**

- 一个 Pi 会话在任一时刻绑定一个检查上下文和一个专用标签页，串行完成采集、局部反馈、复核。
- 浏览器后端留在 Pi 进程外；使用一个固定适配实现，不建立多后端插件框架。
- 同一截图的数据从模型输出到面板再到反馈保持一致，所有等待可取消，失败有明确状态。

**Non-Goals:**

- 自动安装依赖、自动启动或关闭用户 Chrome、连接日常登录配置、云浏览器、多会话并行控制同一端点。
- 整页长截图、自动滚动、任意页面脚本工具、交互回放、源码位置自动映射。
- 独立 HTML 概念稿、实时网页嵌入、视频、像素热图、自动设计评分或自动修复引擎。
- 完整 DOM（文档对象模型）/无障碍树转储、跨域框架内部定位。此类区域仍可用图像框选反馈。

## Decisions

### 1. Browser Harness 为唯一首版后端，先做接入验证

使用外部安装并核对版本的 `browser-harness`。首项验证覆盖专用端点、目录隔离、目标绑定、视口设置、截图实际像素、固定脚本输出及取消。记录测试用的精确 Harness、Chrome、Python、Pi 版本和能力清单；不得将整个 0.1.x 系列视为已兼容。验证无法满足规范时先更新设计，不悄悄换后端。

取舍：`agent-browser` 的结构化命令更完整，但本项目已经选择 Harness 的薄控制层；首版无需依赖其像素比较命令。完整 `browser-use` 库可以独立使用浏览器能力，但增加本轮用不到的依赖。直接自建 CDP 连接、重新实现重连协议或复制参考仓库都没有必要。

### 2. 用户准备专用 Chrome，扩展显式绑定并拥有自己的标签页

首版前置条件是用户通过文档准备专用 Chrome 配置目录与本机开发者工具端点。扩展不自动启动 Chrome，不推断 profile 隔离是否真实存在；界面说明此配置是用户的明确选择。端点仅接受无认证信息的回环 HTTP（超文本传输协议）地址，发现的 WebSocket 地址也必须保持回环，错误或跳转到其他主机时拒绝连接。

通过 `BU_CDP_URL` 和每个检查上下文私有的 `BH_CONFIG_DIR`、`BH_AGENT_WORKSPACE`、`BH_RUNTIME_DIR`、`BH_TMP_DIR` 启动自己的 Harness daemon。运行时路径保持短，避免 macOS 套接字路径长度限制。每端点只允许一个本扩展活跃上下文，跨 Pi 进程的轻量所有权文件检测占用；不接管或终止外部工具的连接。其他控制器仍能修改浏览器，采集前后检查是必要的失效检测，不是浏览器级排他保证。

开发页面首版仅接受 `http`/`https` 加精确回环主机 `localhost`、`127.0.0.1`、`[::1]`，拒绝用户信息、文件地址、外部顶层路由和端点回退。外部资源如字体或图片不因此全部拦截；这是顶层页面范围约束，不是完整网络沙箱。重定向离开范围则停止采集和展示，并说明导航请求已发生。

配置读取顺序为用户级 `<agentDir>/xpi-visualoop.json`，然后仅在 `ctx.isProjectTrusted()` 为真时应用 `<cwd>/.pi/xpi-visualoop.json`；agentDir 用安装版本提供的方式解析。配置只包含 Harness 可执行文件、端点、可选 Glimpse 模块路径，拒绝未知字段及任意启动参数。工作目录和脚本目录由扩展控制。配置中的程序和模块路径代表执行信任，不允许来自页面或模型工具参数。

### 3. 四个工具保持观察、准备与用户输入的边界

| 入口 | 输入要点 | 行为与结果 |
| --- | --- | --- |
| `visual_prepare` | 本地 URL、可选 viewport、DPR、stateLabel | 显式创建/准备绑定标签页，设置视口，导航；返回检查上下文与实际条件。再次准备只导航自有标签页并更新声明状态，不静默重用用户标签页 |
| `visual_capture` | 可选 selector、stateLabel | 当前视口采集；stateLabel 默认继承准备时的声明。返回证据、图像和诊断，不改变页面条件 |
| `visual_feedback` | captureId 或 comparisonId，二选一 | 打开单次反馈/比较面板，等待有效提交、认可或取消并通过该工具结果返回 |
| `visual_verify` | baselineCaptureId、可选 stateLabel | 对同一上下文重新采集，继承基准目标，检查可比较性，返回 comparisonId 和两份证据 |

`stateLabel` 是调用方对交互状态的声明，如 `initial`、`dialog-open`，不能被当作浏览器自动证明。输入说明会要求在人工交互后更新声明；比较结果同时列出可观测字段和仅声明字段。选择器参数只接受数据，唯一匹配通过固定脚本检查。

保留 `/xpi-visualoop` 状态入口，并增加 `disconnect` 子操作取消本扩展检查上下文、释放所有权和临时资源；它不关闭用户 Chrome。首版不额外提供独立 `visual_inspect`：有 selector 的 capture 覆盖此需求。

### 4. 固定脚本协议与受控子进程

通过 Node 标准库 `child_process.spawn()` 启动外部 Harness，`shell: false`。stdin 只传扩展随包提供的固定 Python 脚本和经过 JSON（JavaScript 对象表示法）序列化、编码的数据载荷；不拼接选择器为 Python/JavaScript 代码。Python 脚本只调用已验证的 Harness helpers，必要的固定 JavaScript 仅用于读取元素、样式和就绪状态。CDP 的导航、视口设置等变更只在 prepare 路径使用。

stdout 约定为一个版本化结果信封，TypeScript 严格校验成功/错误结构和资源路径，stderr 有界收集并脱敏；额外横幅、截断或格式错误不能当成功。限制输出并超量终止子进程，而不是在无限缓冲后再截断。

子进程只继承运行必需的环境白名单，不改写宿主 HOME。显式设置 `BH_RECORD=0`、`BH_TAB_MARKER=0`、`BH_TELEMETRY=0`，清除云自动启动、外部 CDP 覆盖、调试截图及不相关凭据。私有工作区不加载用户可编辑 helpers 或项目 `.env`；接入验证必须确认实际导入行为和横幅/后台输出。不得运行更新、录制或云启动命令。

取舍：`pi.exec()` 在当前类型中不能表达 stdin/env；不用 shell heredoc 绕过。首版不增加 MCP（模型上下文协议）客户端，亦不直接调用 Harness 私有套接字协议。

### 5. 最小证据模型与固定预算

三种记录保存在内存索引中，图像放私有临时目录；标识由扩展生成，不接受调用方提供文件路径。

- Capture：id、sessionEpoch、inspectionId、document/target identity、时间区间、URL/title、viewport、DPR（设备像素比）、scroll、浏览器版本/已知字体与颜色环境、stateLabel、就绪状态、图像尺寸与来源区域、可选目标边界/样式、诊断观察范围。
- Feedback：id、captureId、可选 comparisonId、sourceImageId、原图 region、comment、submitted 时间。区域属于图像，不是实时 DOM 元素。
- Comparison：id、beforeCaptureId、afterCaptureId（采集失败时为空）、共同区域、comparable 状态、原因及字段变化。用户验收是单独结果，不修改原证据。

首版默认 viewport 为 1440×900、DPR 为 1；prepare 可传入有效有限值，范围为宽 320–2560、高 240–1600、DPR 1–2，应用后记录实际值。源码没有提供截图坐标正确性的自动保证，必须从实际图像尺寸和页面覆盖范围建立比例。

初始预算作为内部常量及文档说明，不引入配置矩阵：单张导出图最长边 2000 像素且不超过 4 MiB（约 419 万字节）；拒绝或等比缩小后再验证，禁止无声裁去内容。单次 JSON 结果最多 64 KiB，面向模型的文本最多 16 KiB；控制台和网络失败各最多 20 条并标记截断；用户意见最多 2000 字符。操作总时限 30 秒、就绪等待最多 5 秒、面板等待最多 10 分钟。缓存在一个上下文内最多 20 次采集且总计 128 MiB，达到上限时明确要求 disconnect/restart，不淘汰仍被引用的基准。原始截图、局部图和临时中间文件均计入预算。

### 6. 截图与结构信息的一致性有界

先验证目标和页面条件，等候文档/字体/可见图片；浏览器应用是否完成 hydration（客户端接管页面）不能仅凭网络空闲确定。默认不禁用动画或注入页面样式。稳定性检查在有限窗口中比较路由、滚动和目标边界，仍无法证明画布或所有异步内容不变，必须保留限制说明。

在同一串行操作内记录截图前后的元数据，获得一次视口图；元素局部图用 Harness 已依赖的 Pillow 从该图裁切，不再拍第二张不同时间的元素图。用实际输出宽高计算横纵缩放，保留裁切偏移；模型和用户查看同一导出版本。需要局部放大时展示派生图并保留父图引用。

读取必要的 width/height、margin/padding/gap、字体、颜色、边框及 overflow；只收集目标及有界近邻的文本和可用无障碍属性，不遍历整站。选择器失效时普通 capture 返回目标错误；verify 仍可保留成功的视口图，将比较标为 not-comparable。

诊断从扩展建立的观察窗口收集，按 target/session 过滤，输出允许字段与脱敏消息；不输出认证头、Cookie、请求正文。接入验证确认 Harness 事件缓冲与清空语义；不能可靠取得的历史标记 unknown。CDP 诊断订阅属于观察所需设置，不授权页面交互。

### 7. Glimpse 单次反馈，工具结果回传

可选加载用户显式配置的 Glimpse 模块；不硬编码开发机器路径、不复制 native binary。面板只渲染扩展构造的静态 HTML、受限图像与经过转义的文本，不嵌入被检查页面、外链脚本或任意预览内容。布局遵守 `DESIGN.md`，实现时加载 Glimpse 设计技能和当前接口文档。

一个等待中的工具对应一个面板，状态为 `pending / submitted / accepted / cancelled / unavailable`。comparison 模式多出“认可本次结果”，并允许在 after 图上提交下一条意见。正常 capture 模式需要区域和非空文字。支持拖动、缩放、图像滚动、坐标数字输入、可见焦点与键盘操作；多行意见中 Enter 保留换行，显式提交按钮/快捷键提交，Esc 取消。

面板返回的全部数据在 Node 层再次验证。反馈通过原来的工具 Promise 返回，不调用 `sendUserMessage()` 再触发一轮，避免同一次提交双重送达。窗口关闭、超时、AbortSignal、sessionEpoch 变化只允许完成一次。提交后 Agent 是否修改代码仍受原任务授权约束。

无 Glimpse 时 `ctx.hasUI` 为真可用 Pi 原生文字对话降级，明确整图范围；comparison 模式仍可返回明确认可或文字意见。无对话界面时返回 unavailable。远程图形桌面和 Fedora 的窗口依赖不假定可用，桌面验证须记录实际平台，未验证平台明确注明。

### 8. 复核提供证据，不判定设计优劣

`visual_verify` 继承基准目标，按记录的检查条件比对当前状态；不重放导航或交互。浏览器重启、路由/scroll/viewport/DPR 或声明状态不同、图像映射无法对齐、就绪不稳定均返回 not-comparable。同一浏览器会话中的已知字体加载状态和环境要记录，不能声称固定了操作系统全部字体。

目标位置、字体、颜色和尺寸的改变正是待验证内容，不作为全局环境不匹配；输出变化摘要。局部对比取前后目标可见边界的并集，在两张父图的共同视口中裁切，标注超出视口部分。不对齐时只展示明确标记的两张原图。

首版只做并排图与元数据/样式差异，不添加像素差异库。图像相同、不同或采集成功都不生成设计通过结论。只有 comparison 面板明确认可返回 accepted；取消仍是未验收。

### 9. 生命周期、文件与实现边界

使用单一 sessionEpoch 和少量状态记录；会话开始/切换/结束及扩展重载时取消操作、关闭面板、失效记录。重连创建新的 inspectionId，旧证据不能冒充同一浏览器环境。每个端点串行执行完整“检查目标—读取—截图—复查”段；目标身份变化立即中止。

临时目录私有，截图文件仅本人可读写；路径必须留在扩展拥有的目录，防止穿越和符号链接逃逸。释放本扩展创建的标签页/daemon 前核对所有权；遇到待确认离开或未保存内容不强制关闭，报告保留资源。用户 Chrome 进程及专用 profile 永不由清理逻辑删除。失败和硬崩溃后无法承诺立即清理，下一次只检查有所有权标记且进程已失效的残留。

模型工具结果中的图像可能进入 Pi 会话文件并发送给当前模型服务；清理临时目录不删除这些副本。说明文档必须明确这条边界，不提供“本地采集所以不出本机”的承诺。

建议的职责文件为入口注册、Harness 适配及固定脚本、证据/比较逻辑、反馈面板；按真实职责拆分，不创建单实现接口工厂、持久化数据库或队列服务。

## Risks / Trade-offs

- [专用 Chrome 需要一次准备] → 提供 macOS/Fedora 的可验证设置说明和只读诊断，明确 profile 隔离前提；不自动接管日常浏览器。
- [Harness 版本及环境加载行为变化] → 先验证精确版本和能力，固定协议、私有配置目录及失败闭合；不自动升级或替换后端。
- [浏览器状态不是原子快照] → 采集前后核对已知条件，提供时间区间和 unknown/degraded 原因；比较结论只覆盖已核对条件。
- [外部控制器仍能操作同一个端点] → 使用专用环境、自有标签页、端点占用检测和串行操作；检测到目标漂移立即失败。
- [大量截图占用磁盘与模型上下文] → 有界缓存和工具输出，反馈只引用必要图像，生命周期清理，不无限追加图片。
- [Glimpse 平台依赖缺失] → 基础采集独立可用，提供明确的文字降级；不把未验证平台记作完整桌面体验通过。

## Migration Plan

1. 仅在后续显式 apply 后执行实现。先验证 Harness/Pi/Glimpse 接入并记录证据，再交付采集、反馈、复核三个增量。
2. 随实现同步类型、工具描述、双语 README、必要安装说明与术语；只记录本轮验证过的版本和平台。
3. 自动测试覆盖坐标/比较/生命周期，真实浏览器和原生窗口冒烟覆盖主流程及关键失效场景；分别通过 `pnpm typecheck`、`pnpm -w run lint`、`pnpm test`。
4. 回滚通过移除本扩展加载或回退本变更的实现恢复原状态命令；先 disconnect，清理仅限本扩展资源。没有数据库迁移，也不改变用户 Chrome 配置。
