## Why

Agent 与用户在本地开发页面上缺少共享、可定位的视觉事实。截图能表达外观问题，但若没有固定页面状态、区域坐标和反馈引用，修改会在多轮描述中漂移；现在需要把真实页面观察、局部反馈和修改后复核收敛为 Pi 内的可追踪闭环。

## What Changes

- 新增本地开发页面的视觉采集能力，输出截图、页面元数据和受限的结构化定位信息。
- 新增不可变的视觉证据记录，使用户反馈绑定到具体截图、视口、滚动位置和坐标空间。
- 新增 Glimpse 反馈面板，支持查看截图、框选区域、填写文字意见、提交或取消。
- 新增修改前后视觉复核，生成同一检查上下文下的对比结果，并区分可比较与不可比较状态。
- 使用外部 `browser-harness` 作为首选浏览器后端，通过专用 CDP（Chrome DevTools Protocol，Chrome 开发者工具协议）浏览器环境服务本地开发页面。
- 页面准备和导航作为显式操作；视觉采集不隐式导航、滚动或调整视口。首版不向 Agent 开放点击、输入、任意页面脚本执行或自动修复；内部固定的只读采集脚本用于获取页面元数据。

## Capabilities

### New Capabilities

- `visual-evidence`: 采集、固定和引用本地开发页面的视觉证据。
- `visual-feedback`: 用户对截图局部进行框选、评论并将反馈交回当前 Pi 会话。
- `visual-verification`: 在修改前后复用检查上下文，生成有边界的视觉比较结果。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `src/` 中的 Pi 扩展工具、会话状态和 Glimpse/TUI（终端用户界面）展示。
- 增加对外部 `browser-harness` 命令及专用 Chrome/CDP endpoint 的运行时依赖约定，不把浏览器依赖打入 Pi 扩展包。
- 可能新增最小的视觉证据类型与内部序列化格式；不修改 Pi 系统提示词，也不默认持久化用户浏览记录。
- 需要补充类型检查、Biome 检查、Vitest 测试和本地浏览器冒烟验证。
