## Context

当前浏览器后端是外部命令：`src/visual-loop/harness.ts` 用 `spawn(config.harnessPath)` 启动一个 Python 程序，把一段固定的 Python 脚本经 stdin 送入，靠 stdout 的单条 JSON 取回结果。脚本内部使用 `browser_harness.helpers` 与 PIL 完成截图、裁剪、页面信息与事件收集。配置面在 `config.ts`，只有三个键：`cdpUrl`、`harnessPath`、`glimpseModulePath`。

约束来自三处，均已核实：

- Pi 包机制安装时只执行 `npm install`（官方 `docs/packages.md`），没有 pip 或 uv 钩子，因此 `harnessPath` 指向的 Python 程序无法随包分发。
- 本项目 spec 要求不向 Agent 开放点击、输入、任意页面脚本执行或自动修复（`proposal.md` 与 `research.md`），后端能力面必须保持只读。
- 现有代码已把浏览器侧能力收敛为四个固定动作：`prepare`、`capture`、`crop`、`close`，加一个 `--reload`。其余能力（daemon 多路复用、录制、遥测、云浏览器、MCP 端点）从未被调用。

真机环境：macOS、Pi 0.85.1、Chrome 152、Node 24.20。`docs/references/browser-harness` clone 已删除，真机配置中的 `harnessPath` 当前指向不存在的路径。

## Goals / Non-Goals

**Goals:**

- 让扩展在只装自身运行时依赖的环境里可完整运行，运行时依赖增量为零。
- 把「可比性」与「复核输出量」收敛为可单点验证的判据，消除静默比错与上下文预算耗尽两条路径。
- 保持只读边界与现有工具的对外语义不变，使已通过的真机闭环在迁移后仍然成立。

**Non-Goals:**

- 不引入 daemon 或跨 Pi 会话共享的浏览器连接。本项目按检查上下文互斥占用端点，语义与长连共享相反，不在此变更中改变。
- 不实现点击、输入、任意页面脚本执行、自动修复、像素差异热图或录制。
- 不实现 `DevToolsActivePort` 自动发现或浏览器自动启动。端点仍由用户显式配置，保持「无隐式副作用」。
- 不引入 Playwright、`chrome-remote-interface`、MCP 适配器或任何第三方浏览器运行时。

## Decisions

### 决策一：传输层用 Node 内置 `WebSocket`，不用 `ws`

CDP 是 WebSocket 上的 JSON-RPC。Node 24 内置 `WebSocket`（已在本机验证 `typeof WebSocket === "function"`），可收发文本帧，足以承载请求、响应与事件。

- 选它：运行时依赖增量为零，符合「不新增依赖」的目标。
- 备选 `ws`：生态成熟，提供 ping/pong 保活、自定义 agent 与更细的握手控制。`pi-browser-harness@0.11.0` 走的是这条路。
- 备选 `chrome-remote-interface`：只需少量方法，引入它属于为一个薄层套一层封装。
- 决策：先用内置实现；若实测发现保活或握手能力不足，回退到 `ws`。回退点记录在风险一节。

### 决策二:连接生命周期等于检查上下文生命周期

现状每次调用启动一个新进程,因此「断连语义」在当前设计里不存在。改为进程内连接后必须显式选择。同时诊断收集(控制台错误与网络失败)依赖 CDP 推送事件,需要观察窗口。

- 选它:连接在 `prepare` 时建立,在 `close` 时释放,生命周期等于检查上下文。诊断因此获得真实观察窗口,`Log.enable` 与 `Network.enable` 可以接收两次操作之间的事件。
- 备选「每次操作一个短连」:省去状态机,但诊断收集的 `unknown` 会是常态而非异常,两次操作之间的控制台错误与网络失败无法观察。
- 备选「长连 + 跨会话复用」:省去握手开销,但引入重连时序、事件缓冲与陈旧 target 三类新不确定性,且与「互斥占用端点」的现有语义冲突。
- 决策:连接生命周期 = 检查上下文生命周期。代价是需要显式管理连接状态,但诊断能力从「几乎总是 unknown」变为「真实观察」,且与现有「prepare/close 定义所有权窗口」的语义对齐。
### 决策三：按区域裁剪交给浏览器截图接口，删除裁剪动作与图像库

CDP 的 `Page.captureScreenshot` 接受 `clip`，其复合类型 `Page.Viewport` 的 `x` / `y` / `width` / `height` 官方语义是 DIP（device independent pixel，设备无关像素），与现有元素边界 `visibleBounds` 的 CSS 像素同系。因此：

- 选它：一次截图请求直接产出所需区域，`crop` 动作、PIL 依赖与 `/tmp` 往返全部消失。
- 备选：保留 Python 裁剪。依赖无法分发，已否决。
- 决策：用 `clip`。现有 `scale_x = raw_width / page_before["w"]` 的换算随之删除。

未验证项：`clip.scale` 是页面缩放因子（与 DPR 相乘），能否用它把输出像素精确压到 2000px/边的上限，尚未实测。作为兜底，准备阶段把视口限制到 1000×1000（2× 屏输出正好 2000px）。这一点在任务中以真实 Chrome 验证，不靠推断。

### 决策四：可比性由单一函数产生，复核不再二次判断

现状两处判定不一致：`evidence.ts` 的 `compareCaptureConditions` 只把降级就绪记为原因，而 `context.ts` 单独硬拒降级的修改后证据。同一次复核的结论取决于走哪条路径。

- 决策：`compareCaptureConditions` 成为唯一判据来源，`context.ts` 只消费它的结果；降级语义在该函数内一次定义。
- 理由：不变量应写在数据判据里，不写在调用路径的散文里。

### 决策五：`stateLabel` 必须由调用方显式声明，缺失即拒绝

`context.ts` 的 `input.stateLabel ?? before.stateLabel` 会在调用方沉默时沿用基准声明，于是「页面已被点击但未声明」也能得到 `comparable`——这是安全失败的反面。

- 决策：基准声明过 `stateLabel` 而调用方未传时，复核拒绝并给出可执行的提示（传入同一标签，或显式确认状态未变）。
- 备选一：把 `stateLabel` 降级为纯描述字段，可比性只用客观条件判定。否决，因为交互状态变化往往不改变 URL、滚动位置或视口，放弃声明检查等于放弃唯一能发现「页面已被交互改变」的信号。
- 备选二：只补文档。否决，静默路径仍然存在。
- 代价：调用方多一个必填语义；已通过的真机流程需要多传一个参数。这是一次有意的行为收紧，在 `proposal.md` 中标记为行为变更。

### 决策六：复核默认只返回共同区域前后图，视口整图改为显式请求

现状一次复核最多注入四张图（前后视口图 + 前后共同区域图），合计约 21MiB base64，远超采集路径 16KiB 的文本预算。

- 决策：默认只回共同区域的前后图（这是模型真正用于比对的信息）；视口整图需调用方显式请求。结构化比较结果套用与采集结果相同的文本预算检查。
- 理由：上下文预算先于证据配额耗尽，真正的成本边界在这里而不在采集计数上。
- 备选：整体调低图像像素上限。否决，会同时损害需要整页观察的场景。

### 决策七：`harnessPath` 移除并显式拒绝，不静默忽略

配置解析当前是 fail-closed 且拒绝未知字段。移除后端路径字段后，若直接忽略，老配置会「安静地不起作用」。

- 决策：识别到该字段时返回明确的迁移诊断，说明它已移除及其替代方案，并保持 fail-closed。
- 理由：与现有 `config.ts` 对未知字段的态度一致，且用户手上确实有一份失效的真机配置需要被提示。

## Risks / Trade-offs

- **Chrome 144+ 的连接级授权弹窗** → 上游用辅助程序绕开前台弹窗,本方案直连会撞上。真机 Chrome 152 是唯一能一票否决整个方案的未知项。缓解:在任务 1.x 加五分钟连通性 spike:内置 `WebSocket` 直连一次 `/json/version` 与一个 target,看有无弹窗、弹几次。若弹窗是每连接一次且短连模式就是每次操作弹一次,可用性直接归零,这是决策二改为长连的第二个理由。文档明确引导用户授权一次;若弹窗导致自动化流程不可用,退化为「每次会话首次操作前提示用户点击允许」。
- **输出像素上限不可控** → 以真实 Chrome 在 1× 与 2× 屏各测一次;超限时先在准备阶段收紧视口,仍不行则在扩展侧做等比缩小(此时才考虑引入最小图像处理)。
- **事件路由串台** → `Target.attachToTarget` 用扁平模式后事件带 `sessionId`,必须按 `sessionId` 过滤。缓解:连接层统一丢弃不匹配的事件,并以测试固定该行为。
- **行为收紧导致既有流程失败** → `stateLabel` 拒绝会使当前真机流程多一步。缓解:错误信息给出可直接照做的下一步,并在 README 与工具描述中同步契约。
- **只读边界的回归** → 新客户端容易顺手加入更多 CDP 方法。缓解:动作接口固定为四个,测试断言不存在点击、输入与脚本执行路径。
## Migration Plan

1. 保留 `cdpUrl` 语义不变；`harnessPath` 改为显式拒绝并给出替代说明。
2. 用户侧迁移：删除 `harnessPath` 键；无需再安装 Python 或浏览器自动化命令行工具。
3. 真机配置当前指向已删除的仓库内路径，需在实现前改为仅含 `cdpUrl`（必要时应先备份该文件）。
4. 回滚：`harness.ts` 的整体替换以单次提交完成，且旧实现路径在迁移期通过配置拒绝诊断可达，回滚即还原该文件与 `config.ts` 的字段清单。
5. 发布说明需标注这是一次配置破坏性变更，并给出迁移前后的配置示例。
